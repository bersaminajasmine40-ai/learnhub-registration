Understanding Input Validation and Sanitization

  • Input validation checks whether the submitted data follows the required rules. For example, the email field must look like an email address, and the age must be between 18 and 100.
  • Input sanitization or safe input handling helps prevent submitted content from being interpreted in an unsafe way. This helps reduce security problems.
  • HTML attributes such as required, type="email", min, max, minlength, maxlength, and pattern help enforce input rules before the form is submitted.
  • HTML validation alone is not enough. Client-side validation can be bypassed, so real applications must also validate data on the server and apply proper security controls.
  • User-submitted text should be displayed as safe text, not automatically interpreted as HTML or JavaScript.
const userText = "<script>alert('bad script')</script>"; messageElement.textContent = userText;

The example above uses textContent, which displays the text safely. If a developer used innerHTML, the browser could try to interpret the content as HTML.

Reflection

  1. What is the difference between validation and sanitization? Validation checks whether input matches the expected format. Sanitization helps make input safe before storing or displaying it.
  2. Which HTML attributes did you use, and why? We used required, type, min, max, minlength, maxlength, and pattern to make sure the form accepts only valid and useful data.
  3. Why should developers never rely exclusively on client-side validation? Because users can bypass browser checks. Server-side validation is still required for security and reliability.
  4. How should a website safely display user-submitted text? It should display the text as plain text using textContent instead of treating it as HTML.
